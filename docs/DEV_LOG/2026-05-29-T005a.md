# 开发日志 — 2026-05-29 (M1-T005a)

## 任务：M1-T005a — agent_plan 接入 ProjectSettings 校验

### 背景

M1-T003 创建了 ProjectSettings 统一配置读取层，但 agent_plan.py 仍使用独立的 `_load_project_config()` 直接 `yaml.safe_load`，不做结构校验。M1-T005a 是最小步迁移，只在 `_load_project_config` 中添加验证调用。

### 修改

#### src/backend/app/runtime/agent_plan.py

`_load_project_config()` 中新增两行：

```python
from src.backend.app.config import ProjectSettings
ProjectSettings.from_yaml(path)  # 关键字段缺失 → ValueError
```

在返回原始 dict 之前调用。返回类型不变（仍是 `dict[str, Any]`），下游零改动：

- `create_agent_plan()` — 不变
- `hook_manager.run_before_plan(project_config, ...)` — 仍接收 dict
- `scheduler.create_scheduler_plan(pipeline, project_config)` — 仍接收 dict
- `agent_runtime.py` — 仍接收 dict

### 设计决策

| 决策 | 原因 |
|------|------|
| 校验在 `_load_project_config` 而非 `create_agent_plan` | 这是唯一的配置入口点，PLAN 和 EXECUTE 都经过这里 |
| 仍返回 dict，不返回 ProjectSettings | 保持 hook_manager/scheduler/agent_runtime 接口不变 |
| 读两次 YAML | 开销可忽略（<1KB），避免引入缓存复杂性 |
| `third_party.spm_dir/dpabi_dir` 仍为关键字段 | Python-only pipeline 场景当前不存在，后续通过单独的 config 模板解决 |

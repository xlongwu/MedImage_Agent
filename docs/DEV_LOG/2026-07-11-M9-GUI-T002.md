## Summary

Completed M9-GUI-T002: full GUI/manual Approval and Human-in-the-Loop (HITL) design document. This task defines the architecture for how GUI agent actions will be approved, confirmed, audited, and aborted in future M9 phases — without implementing any of it.

## Key Design Decisions

### Three-Layer Approval Model

1. **Session-Level Approval** — creates the GUI session boundary: target app, provider, allowed tiers, file scope, screenshot/clipboard policy, step limit, duration limit, human-present flag
2. **Action-Plan Approval** — user reviews structured action sequence with natural-language descriptions before execution begins
3. **Per-Action Confirmation** — every Tier 2+ action requires individual user confirmation with semantic text (not just `approved=true`)

### `approved=true` Is Insufficient

The current single boolean approval gate in `gui_agent.py` cannot distinguish between:
- A mock recorded observation
- A real `click` on the SPM "Run" button
- A `type_text` of a password

Each requires different approval levels. The design mandates semantic, structured approval per action tier.

### Provider Policy

- **MockGuiProvider**: default, safe for CI, no real desktop control
- **PyWinAutoGuiProvider**: disabled by default; requires `MEDIMAGE_GUI_AGENT_REAL_PROVIDER=1` + structured session approval + per-action confirmation + human-present flag
- **CI**: real provider blocked unconditionally

### Integration Strategy

Compared two options:
- **Option A**: Route GUI through reviewed execution pipeline
- **Option B**: Add equivalent 12-gate guard to GUI agent API

**Recommendation: Option B Phase 1** — add policy validation layer to `/api/gui-agent/*` without modifying reviewed execution. Defer full integration to Phase 2.

### Action Tier → Approval Mapping

| Tier | Approval Required |
|------|:---:|
| Tier 0 (read-only observation) | Session approval only |
| Tier 1 (low-risk navigation) | Session + window scope |
| Tier 2 (medium-risk interaction) | Session + Action-Plan + Per-Action |
| Tier 3 (high-risk / blocked) | Blocked by default; requires separate contract |

## 一、Executor 入口分析

### 当前入口函数

```python
def run_pipeline(
    project_config_path: str | Path,
    pipeline_path: str | Path,
) -> dict[str, Any]:
```

**输入契约**：
1. `project_config_path` — YAML 文件路径（如 `examples/project_config_dataset.yaml`）
2. `pipeline_path` — YAML 文件路径（如 `examples/pipeline_mvp.yaml`）

**内部流程**：
1. `load_project_config(path)` → dict
2. `load_pipeline_yaml(path)` → `PipelineSpec` dataclass（通过 `validate_pipeline_dict()`）
3. 遍历 `pipeline.nodes`，逐节点执行

**关键约束**：
- executor 期望 `PipelineSpec.nodes` 是 `PipelineNode` dataclass 列表
- `PipelineNode` 需要字段：`id`, `backend`, `depends_on`, `params`, `parallel_level`, `gpu_supported` 等
- 有 `version` 字段（必需）

## 二、Reviewed Plan vs Executor Pipeline 格式差异

### Planner 生成的 candidate plan（dict）

```json
{
  "pipeline_id": "planned_motion_qc",
  "nodes": [
    {
      "id": "data_inspection",
      "backend": "python",
      "depends_on": [],
      "params": {}
    }
  ]
}
```

### Executor 期望的 Pipeline YAML（dict → PipelineSpec）

```yaml
pipeline_id: planned_motion_qc
version: "0.1.0"        # ← 必需，candidate plan 无此字段
modality: synthetic-rsfmri
description: "..."      # ← 可选，candidate plan 无
execution:               # ← 必需，candidate plan 无
  run_id: run_001
  stop_on_failure: true
nodes:
  - id: data_inspection
    name: Data Inspection
    agent: data-inspector
    backend: python
    depends_on: []
    params: {}
    parallel_level: project
    gpu_supported: false
    cache: false
```

### 差异总结

| 字段 | candidate plan | executor YAML | 差异 |
|------|:---:|:---:|------|
| `pipeline_id` | ✅ | ✅ | 一致 |
| `version` | ❌ | ✅ 必需 | **缺失** |
| `modality` | ❌ | ✅ | 可默认 "synthetic-rsfmri" |
| `description` | ❌ | ✅ | 可默认空字符串 |
| `execution` | ❌ | ✅ 必需 | **缺失**（含 run_id, stop_on_failure） |
| `nodes[].id` | ✅ | ✅ | 一致 |
| `nodes[].backend` | ✅ | ✅ | 一致 |
| `nodes[].depends_on` | ✅ | ✅ | 一致 |
| `nodes[].params` | ✅ | ✅ | 一致 |
| `nodes[].name` | ❌ | ✅ | 可从 Tool Catalog 推断 |
| `nodes[].agent` | ❌ | ✅ | 可默认 "system" |
| `nodes[].parallel_level` | ❌ | ✅ | 可从 Tool Catalog 推断 |
| `nodes[].gpu_supported` | ❌ | ✅ | 可默认 False |
| `nodes[].inputs/outputs` | ❌ | ✅ | 可默认空 list |
| `nodes[].cache` | ❌ | ✅ | 可默认 False |

## 三、是否需要转换层：✅ 需要

结论：**需要 `reviewed_plan_to_pipeline_dict()` 转换函数。**

建议新增：

```text
src/backend/app/planner/plan_adapter.py
```

核心函数：

```python
def reviewed_plan_to_pipeline_dict(plan: dict[str, Any], run_id: str) -> dict[str, Any]:
    """Convert a candidate plan dict to a pipeline dict that can be
    passed to load_pipeline_yaml → PipelineSpec."""
    from src.backend.app.runtime.tool_catalog import build_tool_catalog
    catalog = {item.id: item for item in build_tool_catalog()}

    nodes = []
    for node in plan.get("nodes", []):
        nid = node.get("id", "")
        cat = catalog.get(nid)
        nodes.append({
            "id": nid,
            "name": cat.name if cat else nid,
            "agent": "system",
            "backend": node.get("backend", cat.backend if cat else "python"),
            "depends_on": node.get("depends_on", []) or [],
            "params": node.get("params", {}) or {},
            "parallel_level": cat.parallel_level if cat else "project",
            "gpu_supported": False,
            "cache": False,
            "inputs": [],
            "outputs": [],
        })

    return {
        "pipeline_id": plan.get("pipeline_id", "reviewed_plan"),
        "version": "0.1.0",
        "modality": "synthetic-rsfmri",
        "description": "Reviewed plan from Plan Review Console",
        "execution": {
            "run_id": run_id,
            "stop_on_failure": True,
        },
        "nodes": nodes,
    }
```

## 五、第一版 Node Blocklist

通过以下条件阻断：

1. `node.backend` 包含 `matlab` 或 `spm` → 阻断
2. `node.id` 以 `spm_` 开头 → 阻断
3. `node.id` 以 `dpabi_subject_` 或 `dpabi_sandbox` 或 `dpabi_single_function` 开头 → 阻断
4. `validation.manual_required_nodes` 非空 → 阻断
5. `validation.unknown_nodes` 非空 → 阻断
6. `ToolCatalogItem.tags` 包含 `matlab` 且非 contract 类 → 阻断

## 八、Audit 强制策略

真实执行（dry_run=false）时：

- `persist_audit` 必须为 true（前端不可选）
- audit record 必须在 `run_pipeline()` 之前写入
- 写入成功后记录 `audit_id`
- 执行后在 audit record 中回写 `run_id` + final status

## 九、Rawdata Readonly 检查

- `project_config_path` → `ProjectSettings.from_yaml()` → `safety.rawdata_readonly`
- 如果 `rawdata_readonly != True` → 阻断执行
- 不信任前端传入的 project_config

## 十三、风险点

1. **pipeline_executor 需要 YAML 路径**，但 reviewed plan 是 dict — 需要写入临时 YAML 或修改 executor 接受 dict
2. **subject-level 节点需要 dataset_index** — reviewed plan 可能未指定
3. **SPM 节点**如果在允许列表边界上，需要精确的 blocklist 拦截
4. **真实执行生成 outputs** — 需要确认目录存在且 writable

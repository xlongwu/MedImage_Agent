## 4. Consistency Findings

### Finding 1 — API Surface Count ✅ Fixed

**File:** `docs/阶段完成记录/M12_后端接口面冻结.md`  
**Issue:** Text said "7 API surfaces: 5 release, 1 blocked, 1 internal" but the internal surface was not listed in the table.  
**Fix:** Changed to "7 API surfaces: 5 release, 1 blocked, 1 internal (tool catalog access)" and added tool catalog to the table.

### Finding 2 — GPU Classification ✅ Aligned

**All documents** now consistently state: "M8 GPU nodes: scaffold/preflight-only. No CUDA execution. CuPy unavailable in tests (4 skipped)."

### Finding 3 — GUI Agent Classification ✅ Aligned

**All documents** now consistently state: "GUI Agent API: mock-only, record_observation only, PyWinAuto blocked."

### Finding 4 — Real Model Classification ✅ Aligned

**All documents** now consistently state: "Real model not connected. Inference not called. Weights not loaded. Fixture-only baseline frozen."

## 5. Capability Classification (Unified)

### Release-Ready
- Reviewed execution pipeline (12-gate)
- SPM reviewed execution baseline (7 nodes)
- DPABI reviewed execution baseline (20 nodes)
- GUI reviewed execution blocklist (38 tests)
- GUI Agent mock-only guarded API (6 layers, 249 tests)
- Mock adapter / fixture path (5 contract modules, 556 tests)
- Frontend build
- Full test suite (2328 passed, 4 skipped)
- Documentation baseline (25+ docs)

### Mock-Only
- GUI Agent provider: MockGuiProvider only
- Model outputs: 45 static mock fixtures
- GUI adapter path: fixture → adapter → mock guard → mock provider

### Scaffold-Only
- M8 GPU nodes: classification/gating scaffold; no real CUDA compute
- GPU benchmark panel: preflight detection only

### Design-Only
- Real model inference (M11 design docs + contract modules; no runtime)
- Audit file writer (M11 audit contract; no file writes)
- Real GUI automation (M9 design; PyWinAuto blocked)
- Tier 1/2/3 GUI actions (41-action taxonomy; only record_observation executable)
- Remote model provider (M11 design; blocked by contract)

### Blocked
- PyWinAuto, real GUI automation, screenshots, clipboard, mouse/keyboard
- Real model, inference, weights, worker process
- Tier 1/2/3 actions, Run/Execute/Submit
- Audit file writes, raw prompt/output persistence

## 8. Required Future Documentation Policy

When adding any new document or modifying existing ones, ensure:

1. Capability terms (release-ready, mock-only, scaffold-only, design-only, blocked) are used consistently.
2. `CURRENT_STATE.md` is updated with the new phase/task status.
3. `NEXT_ACTIONS.md` reflects the recommended next step.
4. `TASK_BACKLOG.md` marks completed tasks and lists candidate follow-up tasks.
5. Any capability classification change is reflected in all relevant release documents.
6. The test baseline number in any new document matches the current full suite result.

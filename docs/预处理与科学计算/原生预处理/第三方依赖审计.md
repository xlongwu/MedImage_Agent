# Native Preprocessing Third-Party Audit

Status: Phase 01 contract baseline with current implementation note.

Scope date: 2026-06-28.

This document audits the local third-party sources and the current MedImage
preprocessing entry points for the planned Python-native rs-fMRI preprocessing
backend. It is an implementation boundary document, not a claim of numerical
equivalence to SPM or DPABI.

## Current Implementation Note

As of 2026-06-28, the Python-native preprocessing runtime is implemented and
is wired through native full API routes, node registry entries, Tool Catalog
metadata, reviewed preprocessing delegation, and frontend workflow controls.
This audit remains the boundary that forbids runtime MATLAB/SPM/DPABI or
`third_party/**/*.m` execution from the native backend.

Current native spatial stages are clean-room simplified baselines, not direct
ports: realignment is simplified, coregistration is affine/simple,
segmentation is intensity based, and normalization is affine-only. Third-party
SPM/DPABI sources may still be used only for behavior notes or future approved
golden/reference comparison, not as runtime code.

## Runtime Policy

The future `native_preproc` backend must not import, call, shell out to, or
execute MATLAB, SPM, DPABI, or any third-party `.m` file.

Allowed use of third-party sources:

- source audit
- parameter semantics reference
- output naming reference
- golden-output comparison when externally provided
- compatibility documentation

Disallowed use in the native backend:

- `matlab -batch`
- `matlab -r`
- `spm_jobman`
- `DPARSFA_run`
- `DPABI_run`
- dynamic execution of `third_party/**/*.m`

Existing external SPM/DPABI backends remain separate, explicit, approval-gated,
audited, and environment-gated.

## Classification Legend

| Class | Meaning |
| --- | --- |
| A | Must be implemented as native preprocessing core algorithm |
| B | Must be represented as native parameter, QC, or workflow semantics |
| C | Existing Python implementation exists, but SPM/DPABI semantics still need alignment |
| D | External function may be used only as golden/reference behavior |
| E | GUI, display, statistics, or non-rsfMRI scope; not needed for this native backend |
| F | Deferred research item |

Allowed reuse strategies:

- `clean_room_rewrite`
- `behavior_reference_only`
- `golden_output_reference`
- `not_needed`
- `defer`

## Known Gaps

- Current native runtime defaults, API, reviewed workflow, and frontend entry
  points are implemented, but they do not validate equivalence with SPM or
  DPABI outputs.
- Simplified native spatial stages remain simplified or affine-only until
  explicit reference validation and algorithm upgrades are completed.
- SPM/DPABI source audit is function-area coverage, not a full source-code
  translation or line-by-line validation.

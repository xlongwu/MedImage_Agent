# ADR-002: rawdata 只读策略

## Status
Accepted (2025-07-18)

## 上下文

医学影像研究中最严重的事故之一就是意外修改或删除原始数据。我们需要在系统架构层面确保原始数据永远不会被任何代码路径修改。

两种可选方案：

1. **文件系统权限控制**：依赖操作系统的文件权限（如 `chmod a-w`）
2. **架构层强制只读 + 所有输出重定向**：在代码架构和开发规范中强制 rawdata 只读，所有写入操作限制在白名单目录

## 决策

我们选择**架构层强制只读**，辅以文件系统权限控制。

具体决策：

1. **rawdata 永远只读**。`data/` 目录下的所有文件在任何代码路径中只能以只读模式打开。
2. **所有中间结果写入 `outputs/work/`**。每个 pipeline run 的运行时状态和中间文件存储在此目录下（`work/states/<run_id>/`）。
3. **所有衍生数据写入 `outputs/derivatives/`**。所有处理结果（SPM 输出、ALFF/ReHo/FC 结果等）存储在此目录下，按受试者和处理步骤组织。
4. **所有报告写入 `outputs/reports/`**。QC 报告、数据集评估报告、组汇总报告等。
5. **所有导出包写入 `outputs/exports/`**。可复现性捆绑包、报告导出包等。

## 后果

### 正面

- **零风险**：无论任何代码路径或 bug，原始数据不会被修改
- **可追溯**：所有输出按目录分类，便于审计和复现
- **可清理**：需要重置时只需删除 `outputs/` 目录，rawdata 不受影响
- **跨平台**：不依赖特定操作系统的文件权限机制

### 负面

- **数据复制开销**：处理过程中需要从 rawdata 复制数据到 work 目录（对于大型数据集可能耗时）
- **磁盘空间**：输出目录可能累积大量中间结果（需要定期清理策略）
- **路径管理**：所有代码必须遵循输出路径约定，增加开发复杂度

### 风险缓解

- 使用硬链接或写时复制（copy-on-write）减少数据复制开销（未来优化）
- 提供 `outputs/` 清理脚本，按 run_id 或日期清理过期数据
- Path Safety 模块（`path_safety.py`）在 API 层拦截越权访问
- Plan Validator（M3）在执行前检查所有 output 路径是否在白名单目录

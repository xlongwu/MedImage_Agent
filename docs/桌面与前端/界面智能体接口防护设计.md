# GUI Agent API Guard Design

> M9-GUI-GUARD-T001 | Guard design for `/api/gui-agent/*` endpoints  
> Status: DESIGN | Date: 2026-07-11  
> Depends on: M9-GUI-CLOSEOUT, M6–M9 Safety Architecture Review  
> Feeds into: M9-GUI-GUARD-T002 through T006

---

## 1. Executive Summary

This document defines the API guard design for the `/api/gui-agent/*` REST surface. The GUI Agent API currently has five endpoints registered in `main.py` that operate **outside** the reviewed execution 12-gate safety pipeline. This design specifies where and how a multi-layer guard should be inserted to close that gap without modifying the reviewed execution pipeline.

**Key principle:** The guard must make real-provider execution **impossible by default**. The only path through the guard in Phase 1 is `provider=mock` + `action_type=record_observation` under valid session/action declarations. Everything else returns `GUI_GUARD_BLOCKED`.

## 2. Current Bypass Analysis

### 2.1 The Gap

```
Reviewed execution pipeline (12 gates):
  plan_validator → approval_gate → plan_adapter → execute_reviewed
  ├── ✓ Blocks gui_* nodes via blocked_unknown_nodes
  ├── ✓ Blocks manual_required_nodes via MANUAL_REQUIRED_NODE
  └── ✓ Sets executor_called=false for all GUI scenarios

GUI Agent API (/api/gui-agent/*):
  gui_agent_routes.py registered in main.py line 18, 55
  ├── ✗ No plan_validator call
  ├── ✗ No approval_gate call
  ├── ✗ No plan_adapter call
  ├── ✗ No execute_reviewed call
  └── Only gate: approved=true Boolean in create_gui_agent_session()
```

### 2.2 Current Risk

| Risk Vector | Severity | Detail |
|------|:---:|------|
| `provider=pywinauto` | **HIGH** | If env var unset, default is `mock`. But `MEDIMAGE_GUI_AGENT_PROVIDER` can override. |
| `approved=true` Boolean | **HIGH** | Single Boolean gate for real desktop control — no per-action confirmation, no tier classification. |
| No session validation | **MEDIUM** | Any `target_app` string accepted; any `objective` accepted. |
| No action validation | **HIGH** | Any `action` string dispatched to provider; `click`, `type_text`, `menu_select` all reachable. |
| No screenshot gate | **HIGH** | `GET .../screenshot` calls `capture_gui_agent_screenshot()` which can write real PNG via PyWinAuto. |

### 2.3 Current Mitigation (Insufficient)

```python
# gui_agent.py:168-170
provider = payload.get("provider", os.environ.get("MEDIMAGE_GUI_AGENT_PROVIDER", "mock"))
# Default is "mock" — safe. But environment variable can override to "pywinauto".
```

The default is safe, but **no guard prevents switching to pywinauto**. An authorized caller or misconfigured environment could bypass.

## 3. Guard Insertion Points

### 3.1 Option A — Route-Level Guard

Insert guard inside `gui_agent_routes.py` before calling runtime functions.

```
POST /api/gui-agent/sessions
  → parse_request (FastAPI)
  → [GUARD: validate_session_declaration]
  → [GUARD: provider_policy_gate]
  → create_gui_agent_session()

POST /api/gui-agent/sessions/{id}/step
  → parse_request (FastAPI)
  → [GUARD: load_session]
  → [GUARD: validate_action_declaration]
  → [GUARD: action_tier_classifier]
  → [GUARD: policy_gates]
  → [GUARD: stop_condition_checker]
  → [GUARD: audit_log]
  → step_gui_agent_session()
```

**Pros:** Localized, fast to implement, protects current surface.  
**Cons:** May duplicate reviewed execution logic; separate policy layer to maintain.

### 3.2 Option B — Runtime-Level Guard

Insert guard inside `gui_agent.py` before provider calls.

```python
def step_gui_agent_session(session_id, payload):
    session = _read_session(session_id)
    # [GUARD: validate_action_declaration]
    # [GUARD: action_tier_classifier]
    # [GUARD: policy_gates]
    # [GUARD: stop_condition_checker]
    # [GUARD: issue_permission_token]
    # if not permission_token.valid: return blocked
    provider = _provider(...)
    provider.perform_step(...)
```

**Pros:** Protects all callers of runtime; harder to bypass by new routes.  
**Cons:** Runtime may become policy-heavy; API error mapping must be handled carefully.

### 3.3 Option C — Shared Guard Service (Recommended)

Create `src/backend/app/runtime/gui_agent_guard.py` as a shared module used by both routes and runtime.

```
gui_agent_routes.py          gui_agent.py
        │                          │
        └──────────┬───────────────┘
                   │
          gui_agent_guard.py
                   │
    ┌──────────────┼──────────────┐
    │              │              │
  validate_    classify_    check_
  session()    action()     policies()
```

**Recommendation: Option C — Shared Guard Service.** Routes validate request and map errors. Runtime refuses provider calls unless `guard_result.ok=true`. The guard module is independently testable.

### 3.4 File Placement

```
src/backend/app/runtime/gui_agent_guard.py     # NEW: shared guard module
src/backend/app/api/gui_agent_routes.py         # MODIFIED: call guard before runtime
src/backend/app/runtime/gui_agent.py            # MODIFIED: call guard before provider
```

## 4. Guard Pipeline Overview

### 4.1 Session Creation Guard (POST /sessions)

```
Layer 1  → Request schema validation (FastAPI / Pydantic)
Layer 2  → Session declaration validation
Layer 3  → Provider policy gate
Layer 4  → Target application/window scope gate
Layer 5  → Audit log pre-create
Layer 6  → Session creation → Return session_id
```

### 4.2 Step Execution Guard (POST /sessions/{id}/step)

```
Layer 1  → Request schema validation (FastAPI / Pydantic)
Layer 2  → Session load + status check
Layer 3  → Action declaration validation
Layer 4  → Action tier classification
Layer 5  → File/path scope gate
Layer 6  → Screenshot policy gate
Layer 7  → Clipboard policy gate
Layer 8  → Network policy gate
Layer 9  → Approval / HITL gate
Layer 10 → Stop-condition checker
Layer 11 → Audit log
Layer 12 → Issue permission token → Call provider
```

### 4.3 Screenshot Guard (GET /sessions/{id}/screenshot)

```
Layer 1  → Session load + status check
Layer 2  → Screenshot policy gate (must NOT be "disabled")
Layer 3  → Redaction policy check
Layer 4  → Audit log
Layer 5  → Permission token → Call provider.capture_screenshot()
```

### 4.4 Abort Guard (POST /sessions/{id}/abort)

```
Layer 1  → Session load
Layer 2  → Audit log (abort event)
Layer 3  → Call abort_gui_agent_session() — always allowed
```

```json
  "step_limit": 20,
```

### 5.2 Validation Rules

```python
def validate_session_declaration(session: dict) -> GuardResult:
    # MUST be true
    if not session.get("gui_sandbox_mode"):
        return blocked("GUI_GUARD_SESSION_INVALID", "gui_sandbox_mode must be true")

    # Provider policy (checked by provider gate — see Section 7)
    # Deferred to provider_policy_gate()

    # Target application required
    if not session.get("target_application"):
        return blocked("GUI_GUARD_SESSION_INVALID", "target_application required")
    if session.get("target_application") in PERMANENTLY_BLOCKED_APPS:
        return blocked("GUI_GUARD_APP_BLOCKED", f"target_application blocked: {session['target_application']}")

    # Target window required
    if not session.get("target_window"):
        return blocked("GUI_GUARD_SESSION_INVALID", "target_window required")

    # Tier restrictions (Phase 1: Tier 0 only)
    allowed_tiers = session.get("allowed_action_tiers", [])
    if 2 in allowed_tiers or 3 in allowed_tiers:
        return blocked("GUI_GUARD_ACTION_TIER_BLOCKED", "Tier 2/3 not permitted in Phase 1 guard")
    if 1 in allowed_tiers:
        return blocked("GUI_GUARD_ACTION_TIER_BLOCKED", "Tier 1 blocked until T004+")

    # File scope required
    if not session.get("file_scope"):
        return blocked("GUI_GUARD_PATH_SCOPE_BLOCKED", "file_scope required")
    for path in session["file_scope"]:
        if not _is_scoped_path(path):
            return blocked("GUI_GUARD_PATH_SCOPE_BLOCKED", f"Path outside scope: {path}")

    # Hard blocks
    if session.get("allow_rawdata_access"):
        return blocked("GUI_GUARD_PATH_SCOPE_BLOCKED", "rawdata access blocked")
    if session.get("allow_derivatives_write"):
        return blocked("GUI_GUARD_PATH_SCOPE_BLOCKED", "derivatives write blocked")
    if not session.get("human_present"):
        return blocked("GUI_GUARD_SESSION_INVALID", "human_present must be true")
    if not session.get("emergency_abort_enabled"):
        return blocked("GUI_GUARD_SESSION_INVALID", "emergency_abort_enabled must be true")
    if not session.get("audit_log_required"):
        return blocked("GUI_GUARD_AUDIT_REQUIRED", "audit_log_required must be true")

    # Policy gates deferred to respective checkers
    return allowed()
```

## 6. Step/Action Request Validation

### 6.1 Extended Action Declaration Schema

The current `GuiAgentStepRequest` (`src/backend/app/api/models.py:93-95`) has only 2 fields. The guard requires:

```json
{
  "session_id": "gui_abc123def456",
  "step_id": "step_001",
  "action_type": "record_observation",
  "action_tier": 0,
  "read_only": true,
  "target_application": "MATLAB",
  "target_window": "SPM.*Batch Editor",
  "parameters": {"window": "SPM"},
  "input_paths": [],
  "output_paths": [],
  "uses_screenshot": false,
  "uses_clipboard": false,
  "uses_keyboard": false,
  "uses_mouse": false,
  "network_access": false,
  "expected_side_effects": "none",
  "requires_per_action_confirmation": false,
  "approval_id": null,
  "rollback_plan": "none",
  "stop_conditions": ["unexpected_window", "credential_field"]
}
```

### 6.2 Validation Rules

```python
def validate_action_declaration(action: dict, session: dict) -> GuardResult:
    # Session status check
    if session.get("status") == "ABORTED":
        return blocked("GUI_GUARD_SESSION_INVALID", "Session is aborted")

    # Action type must be known
    if action.get("action_type") not in KNOWN_ACTIONS:
        return blocked("GUI_GUARD_ACTION_UNKNOWN", f"Unknown action: {action.get('action_type')}")

    # Tier must be within session's allowed tiers
    declared_tier = action.get("action_tier")
    if declared_tier not in session.get("allowed_action_tiers", []):
        return blocked("GUI_GUARD_ACTION_TIER_BLOCKED", f"Tier {declared_tier} not in allowed tiers")

    # Step limit
    current_steps = len(session.get("steps", []))
    if current_steps >= session.get("step_limit", 20):
        return blocked("GUI_GUARD_STOP_CONDITION", "Step limit exceeded")

    # Duration
    elapsed = _elapsed_seconds(session.get("created_at"))
    if elapsed > session.get("duration_limit_seconds", 300):
        return blocked("GUI_GUARD_STOP_CONDITION", "Duration limit exceeded")

    # Target must match session
    if action.get("target_application") != session.get("target_application"):
        return blocked("GUI_GUARD_STOP_CONDITION", "Target application mismatch")
    if action.get("target_window") != session.get("target_window"):
        return blocked("GUI_GUARD_STOP_CONDITION", "Target window mismatch")

    # Usage flags
    if action.get("uses_mouse") and "mouse" not in session.get("allowed_modalities", []):
        return blocked("GUI_GUARD_ACTION_TIER_BLOCKED", "Mouse use not permitted")
    if action.get("uses_keyboard") and "keyboard" not in session.get("allowed_modalities", []):
        return blocked("GUI_GUARD_ACTION_TIER_BLOCKED", "Keyboard use not permitted")
    if action.get("uses_clipboard"):
        return blocked("GUI_GUARD_CLIPBOARD_BLOCKED", "Clipboard blocked")
    if action.get("network_access"):
        return blocked("GUI_GUARD_NETWORK_BLOCKED", "Network blocked")
    if action.get("output_paths"):
        for path in action["output_paths"]:
            if not _is_within_scope(path, session.get("file_scope", [])):
                return blocked("GUI_GUARD_PATH_SCOPE_BLOCKED", f"Output path out of scope: {path}")

    # Must be read_only for Tier 0
    if declared_tier == 0 and not action.get("read_only"):
        return blocked("GUI_GUARD_ACTION_TIER_BLOCKED", "Tier 0 actions must be read_only")

    return allowed()
```

## 7. Provider Policy Gate

### 7.1 Policy Rules

```python
def provider_policy_gate(session: dict) -> GuardResult:
    provider = session.get("provider", "mock")

    # Mock: always allowed (CI-safe)
    if provider == "mock":
        return allowed(provider="mock", real_provider=False)

    # PyWinAuto: blocked by default
    if provider == "pywinauto":
        return blocked(
            "GUI_GUARD_REAL_PROVIDER_DISABLED",
            "Real desktop provider (pywinauto) is not enabled. "
            "Set MEDIMAGE_GUI_AGENT_REAL_PROVIDER=1 and provide explicit session approval "
            "to enable real desktop control. This is blocked in all current M9 phases."
        )

    # Unknown provider
    return blocked("GUI_GUARD_PROVIDER_BLOCKED", f"Unknown provider: {provider}")
```

### 7.2 Provider State Table

| Provider | Phase 1 Default | CI | Requires Feature Flag | Requires Session Approval |
|----------|:---:|:---:|:---:|:---:|
| `mock` | ✅ Allowed | ✅ Allowed | No | Declaration only |
| `pywinauto` | ❌ Blocked | ❌ Blocked | Yes + guard | Yes + per-action |
| Unknown | ❌ Blocked | ❌ Blocked | — | — |

### 7.3 What Enabling PyWinAuto Requires (Future)

```
- MEDIMAGE_GUI_AGENT_REAL_PROVIDER=1 (environment variable)
- gui_sandbox_mode=true (session declaration)
- provider=pywinauto (session declaration)
- human_present=true (session declaration)
- approved=true is NOT sufficient — must go through full approval/HITL gate
- Per-action confirmation for Tier 2+ actions
- Audit log required
- Screenshot policy enforced
- Stop-condition checker active
- Only after GUARD-T002 through T006 are implemented and tested
```

### 8.2 Classification Function

```python
def classify_gui_action(action_type: str) -> tuple[int, bool]:
    """Return (tier, is_blocked_by_default)."""
    if action_type in TIER_0_ACTIONS:
        return (0, False)
    if action_type in TIER_1_ACTIONS:
        return (1, True)   # blocked in Phase 1
    if action_type in TIER_2_ACTIONS:
        return (2, True)   # blocked in Phase 1
    if action_type in TIER_3_ACTIONS:
        return (3, True)   # permanently blocked
    return (-1, True)       # unknown — blocked
```

### 8.3 Phase 1 Behavior

```
Only Tier 0 actions are not blocked by default.
But even Tier 0 actions require:
  - valid session declaration
  - valid action declaration
  - provider=mock (real provider blocked)
  - no screenshots (screenshot_policy=disabled in Phase 1)
  - no clipboard

Phase 1 permitted action set:
  → record_observation with provider=mock
  → Everything else returns GUI_GUARD_BLOCKED
```

## 9. Policy Gates

### 9.1 Screenshot Policy Gate

```python
def screenshot_policy_gate(session: dict, action: dict) -> GuardResult:
    policy = session.get("screenshot_policy", "disabled")

    if not action.get("uses_screenshot"):
        return allowed()  # No screenshot requested

    if policy == "disabled":
        return blocked("GUI_GUARD_SCREENSHOT_BLOCKED",
                       "Screenshot policy is 'disabled' for this session")

    if policy == "persist_raw":
        return blocked("GUI_GUARD_SCREENSHOT_BLOCKED",
                       "persist_raw is permanently blocked")

    # ephemeral_only and persist_redacted require future guard layers
    return blocked("GUI_GUARD_SCREENSHOT_BLOCKED",
                   f"Screenshot policy '{policy}' not yet implemented in guard")
```

### 9.2 Clipboard Policy Gate

```python
def clipboard_policy_gate(session: dict, action: dict) -> GuardResult:
    if action.get("uses_clipboard"):
        return blocked("GUI_GUARD_CLIPBOARD_BLOCKED",
                       "Clipboard access is blocked in all current phases")
    return allowed()
```

### 9.3 Network Policy Gate

```python
def network_policy_gate(session: dict, action: dict) -> GuardResult:
    if not action.get("network_access"):
        return allowed()

    policy = session.get("network_policy", "disabled")
    if policy == "disabled":
        return blocked("GUI_GUARD_NETWORK_BLOCKED", "Network access is disabled")
    if policy == "local_only":
        # Future: validate destination is localhost
        return blocked("GUI_GUARD_NETWORK_BLOCKED",
                       "local_only network policy not yet implemented in guard")
    return blocked("GUI_GUARD_NETWORK_BLOCKED",
                   f"Network policy '{policy}' not permitted")
```

### 9.4 File/Path Scope Gate

```python
def path_scope_gate(session: dict, action: dict) -> GuardResult:
    file_scope = session.get("file_scope", [])

    for path in action.get("input_paths", []):
        if not _is_within_scope(path, file_scope):
            return blocked("GUI_GUARD_PATH_SCOPE_BLOCKED",
                           f"Input path '{path}' outside file_scope")

    for path in action.get("output_paths", []):
        if not _is_within_scope(path, file_scope):
            return blocked("GUI_GUARD_PATH_SCOPE_BLOCKED",
                           f"Output path '{path}' outside file_scope")

    return allowed()
```

## 10. Approval / HITL Integration

### 10.1 Phase 1 Behavior

```
Mock Tier 0 record_observation:
  - Session declaration REQUIRED
  - Action declaration REQUIRED
  - No per-action confirmation needed (read-only, mock-only)
  - Audit required

All other actions:
  - Blocked until per-action confirmation manager is implemented (GUARD-T005+)
```

### 10.2 Future Three-Layer Model (from T002)

| Layer | Phase 1 | Future |
|:---:|:---:|:---:|
| Session Approval | ✅ Declaration validated | Same |
| Action-Plan Approval | ❌ Not implemented | Required for Tier 1+ |
| Per-Action Confirmation | ❌ Not needed (Tier 0 mock only) | Required for Tier 2+ |

### 10.3 Deprecation of `approved=true`

```
The current approved=true Boolean in GuiAgentSessionRequest is insufficient.
Guard Phase 1 should:
  - Ignore approved=true for mock provider (not needed)
  - Reject approved=true as sole authorization for real provider
  - Require structured approval record for any future real provider use
```

## 12. Stop-Condition Checker

### 12.1 Declaration-Level Checks (Phase 1)

These can be checked from session/action declaration without real UI access:

| Condition | Detection Method |
|------|------|
| Step limit exceeded | `len(session.steps) >= session.step_limit` |
| Duration limit exceeded | `now - session.created_at > session.duration_limit_seconds` |
| Session aborted | `session.status == "ABORTED"` |
| Target application mismatch | `action.target_application != session.target_application` |
| Target window mismatch | `action.target_window != session.target_window` |
| Human not present | `session.human_present == false` |
| Emergency abort requested | Client-side abort flag |

### 12.2 UI-Level Checks (Future)

These require real UI observation capabilities (blocked in Phase 1):

| Condition | Future Detection |
|------|------|
| Credential field visible | OCR / control-type detection on screenshot |
| Permission/security dialog | Window title pattern match |
| Network/upload dialog | Window title pattern match |
| Rawdata path visible | Path pattern in visible text |
| Screenshot policy violation | Provider attempting persist_raw |

## 13. Emergency Abort Design

### 13.1 Abort Is Always Unguarded

```
POST /api/gui-agent/sessions/{id}/abort
  → No guard gates (abort must always succeed)
  → Audit log: ABORT_REQUESTED
  → Call abort_gui_agent_session(id)
  → Session status → "ABORTED"
  → All subsequent step requests → GUI_GUARD_SESSION_INVALID
```

### 13.2 Server-Side Abort

```
Future: background watcher checks:
  - Session duration exceeds limit → auto-abort
  - Provider callback reports unexpected window → auto-abort
  - Heartbeat lost (human_present becomes false) → auto-abort
```

## 16. Fine-Tuned GUI Agent Integration Path

### 16.1 Integration Architecture

```
┌─────────────────────────────────────────────────────┐
│                Fine-Tuned GUI Agent                  │
│  (LLM / vision model — outputs structured intent)   │
└──────────────────────┬──────────────────────────────┘
                       │ structured intent (JSON)
                       ▼
┌─────────────────────────────────────────────────────┐
│              GUI Action Adapter                      │
│  (normalizes model output → GUI Action Schema)      │
│  (rejects raw coordinate outputs)                    │
└──────────────────────┬──────────────────────────────┘
                       │ normalized action schema
                       ▼
┌─────────────────────────────────────────────────────┐
│               GUI Agent API Guard                    │
│  (12 layers: session → action → tier → policies →   │
│   approval → audit → stop → permission token)        │
└──────────────────────┬──────────────────────────────┘
                       │ permission token
                       ▼
┌─────────────────────────────────────────────────────┐
│          MockGuiProvider  │  PyWinAutoGuiProvider     │
│     (safe / CI / tests)   │  (real desktop — future) │
└─────────────────────────────────────────────────────┘
```

### 16.2 Hard Constraints for Model Integration

```
1. Model must output structured action schema, NOT raw mouse coordinates.
2. Raw coordinate output → rejected by Action Adapter.
3. Model must never receive provider reference or permission token.
4. Provider is never directly callable by model output.
5. Model output must pass ALL guard layers before provider is called.
6. Tier 3 actions are rejected by the guard regardless of model intent.
7. Real provider (PyWinAuto) remains blocked until guard + approval/HITL are complete.
```

## 19. Non-Goals and Forbidden Actions

### 19.1 This Design Does NOT Authorize

```
- Implementing real desktop control (PyWinAuto still blocked)
- Opening GUI/manual reviewed execution allowlist
- Enabling screenshot capture or clipboard access
- Allowing Tier 1/2/3 actions in Phase 1
- Creating a bypass for the reviewed execution pipeline
- Exposing provider directly to any model or API caller
```

### 19.2 Forbidden in All Guard Phases

```
- provider=pywinauto without feature flag + structured approval
- Tier 3 actions without explicit per-action confirmation (future)
- Screenshot persist_raw (permanently blocked)
- Clipboard access without per-action confirmation (future)
- Rawdata access through GUI
- Credential entry
- Browser/email/messaging control
- Direct provider call without permission token
```

# MedImage Agent v0.4.0-rc1 — DICOM Conversion Safety Release Candidate

**Status:** Release Candidate — Phase 4 Frozen
**Date:** 2026-06-10

---

## 1. Summary

v0.4.0-rc1 delivers a complete DICOM-to-NIfTI conversion safety framework
for MedImage Agent.  All 32 safety gates are met.  The framework includes
DICOM detection, dry-run mapping, conversion preflight, approval gate design,
audit integration, checksum verification, rollback protection, release
readiness evaluation, and a formal human release approval workflow.

**Public DICOM conversion execution is NOT enabled in this release.**
Internal conversion has been validated on real FunRaw/T1Raw DemoData
(1104 DICOM files, 3 subjects) with rawdata checksum unchanged.

---

## 2. Phase 4 DICOM Conversion Safety Gates

All 32 safety gates met.  Zero partial.  Zero missing.

Key safety features:
- DICOM detection (FunRaw/T1Raw, path-based, no pydicom required)
- Conversion dry-run mapping (6 BIDS/NIfTI previews)
- dcm2niix availability check with version recording
- Approval gate: 17 preconditions, evaluated before execution
- Audit records: start before dcm2niix, final after
- Rawdata checksum before/after verification
- Rollback: dry-run, quarantine, delete modes
- Execution provenance references all evidence
- 10 env flags required for any real execution
- No `shell=True` — all subprocess calls use argv lists

---

## 3. Release Readiness UI

New read-only "Release Readiness" section in the DICOM Conversion Review panel:
- Shows gate status (32/32 met)
- Disk space check with multiplier
- Runtime policy (timeout, cancellation, resume, retry)
- Safety invariant badges
- Blockers and warnings display

**This panel does not run conversion.**  It is read-only evaluation.

---

## 4. Approval / Audit / Rollback Support

- Approval record persistence (10 metadata files per run directory)
- Audit execution start/final records
- Rollback: dry-run, quarantine, delete with confirmation
- Release approval workflow: 9 required fields, schema + service
- Metadata-only audit export (excludes .dcm, .nii, .nii.gz)

## 6. Safety Boundaries

- ✅ Rawdata remains read-only — never modified
- ✅ No public `/conversion/execute` endpoint
- ✅ No frontend "Run Conversion" button
- ✅ `run_conversion_execute()` returns blocked for normal users
- ✅ SPM/DPABI/MATLAB remain disabled
- ✅ Full preprocessing not enabled
- ✅ All subprocess calls use argv lists — no `shell=True`
- ✅ `MEDIMAGE_ALLOW_USER_DATA_CONVERSION=1` NOT set
- ✅ Human release approval required before public enablement

---

## 7. Known Limitations

- NIfTI viewer not included (metadata-only)
- No complete QC dashboard
- No report editor
- MATLAB/SPM/DPABI/GPU are contract-only
- SPM realign is preparation-only
- DICOM conversion is internal-only (no public UI)
- QC Dashboard cache is single-module prototype
- BIDS Validation fail is expected for raw DICOM datasets
- Electron app is unsigned (SmartScreen warning on first run)
- Windows-only packaging
- No auto-update

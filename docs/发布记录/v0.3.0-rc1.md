# MedImage Agent v0.3.0-rc1 Release Notes

**Release Date**: 2026-06-06
**Tag**: `v0.3.0-rc1`
**Type**: Desktop MVP Release Candidate

---

## Overview

MedImage Agent is a **deterministic Plan-then-Execute desktop platform** for
resting-state fMRI (rs-fMRI) research. The LLM plans and advises; execution
remains inside the Pipeline Runtime and registered node runners.

**This is not a clinical diagnosis or clinical decision product.**

v0.3.0-rc1 is the first desktop release candidate. It bundles the full
real-project workflow — from BIDS/rawdata project creation through reviewed
execution through run artifact inspection — in an offline-capable Windows
desktop application.

---

## What's Included

### Desktop Application

- Electron 31 shell with static React frontend
- PyInstaller FastAPI backend sidecar (no Python/Node required at runtime)
- Automatic localhost port selection (8765+)
- Backend health-check gate before UI loads
- Managed backend lifecycle (start on launch, stop on quit)
- Three distribution formats:
  - **NSIS installer** (`MedImage Agent Setup.exe`, 112 MB)
  - **Portable exe** (`MedImage Agent.exe`, 112 MB)
  - **Unpacked directory** (`win-unpacked/`, 181 MB)

### Real Project Workflow

| Step | Capability |
|---|---|
| 1. Create Project | Select local BIDS/rawdata directory; generates `project_config.yaml` and `dataset_index.json` |
| 2. Plan Review | Real project context injected before review; reviewed plan persisted to SQLite |
| 3. Execute Reviewed | Approval Gate gated; unique `run_id` generated per execution |
| 4. Run History | Per-project run list with timestamps, status, warnings |
| 5. Run Summary | Status, node counts, outputs, failed nodes, warnings |
| 6. Artifact Discovery | Run-scoped artifacts from summary, node states, and pipeline outputs |
| 7. Artifact Preview | JSON, CSV, Markdown, text, log content preview; NIfTI/MAT metadata-only |
| 8. QC/Error Summary | Combined health, failed-node info, QC highlights, error excerpts |

### Safety Architecture

- Rawdata is read-only (referenced, never copied or modified)
- Approval Gate mandatory before any file-writing or execution
- Path safety prevents directory traversal
- Artifact preview uses `project_id + run_id + artifact_id` resolution (no arbitrary paths)
- Binary, NIfTI, and MAT files are metadata-only
- Frontend communicates only through backend HTTP APIs
- Desktop bridge (`window.medimage.openExternalPath`) available in Electron runtime

### Internal Validation

- `contract_smoke` node validates executor node contract (pure Python, no external deps)
- Test: `tests/integration/test_node_contract_smoke.py`

Build command (offline, from repository root):

```powershell
$env:MEDIMAGE_ELECTRON_RUNTIME_ZIP="desktop\electron\.electron-cache\manual-runtime\electron-v31.7.7-win32-x64.zip"
$env:ELECTRON_BUILDER_NSIS_DIR="desktop\electron\.electron-builder-cache\manual-nsis\nsis-3.0.4.1"
npm --prefix desktop/electron run dist -- --win
```

## Clean Install Validation Checklist

Use this checklist to validate a fresh installation or portable run.

### Pre-install

- [ ] No previous MedImage Agent installation or `%APPDATA%\medimage-agent-desktop` directory
- [ ] Target machine is Windows 10 (build 19041+) or Windows 11
- [ ] At least 500 MB free disk space

### NSIS Installer

- [ ] Run `MedImage Agent Setup.exe`
- [ ] Windows SmartScreen: click "More info" → "Run anyway" (unsigned build)
- [ ] Choose install directory (default or custom)
- [ ] Installation completes without errors
- [ ] Desktop shortcut created
- [ ] Launch from shortcut → main window appears
- [ ] Backend starts automatically → UI loads (no white screen)
- [ ] `http://127.0.0.1:8765/api/health` returns `{"status":"ok"}`
- [ ] App closes cleanly → no residual `medimage-backend.exe` process

### Portable Exe

- [ ] Run `MedImage Agent.exe` directly (no installation)
- [ ] Self-extraction completes → main window appears
- [ ] UI loads correctly
- [ ] Backend health check passes
- [ ] Close app → temporary extraction directory cleaned up

### Basic Workflow Smoke (either format)

- [ ] Create a project from a local BIDS/rawdata directory
- [ ] `project_config.yaml` generated inside managed project directory
- [ ] `dataset_index.json` generated
- [ ] Plan Review: real project context injected
- [ ] Save reviewed plan → `reviewed_plan_id` listed
- [ ] Execute reviewed plan → unique `run_id` generated
- [ ] Run history shows the run
- [ ] Summary preview displays status, counts, outputs
- [ ] Artifact list displays run-scoped artifacts
- [ ] JSON/CSV/Markdown/text/log artifacts preview correctly
- [ ] NIfTI/MAT artifacts show metadata-only detail
- [ ] Rawdata directory unchanged after execution

### Safety Verification

- [ ] No files written to rawdata directory
- [ ] Outputs go to managed project output roots (not rawdata)
- [ ] MATLAB/SPM/DPABI/GPU are not invoked
- [ ] Artifact preview rejects paths outside project scope
- [ ] Frontend does not access local filesystem directly (only via bridge)

## Known Limitations

| Limitation | Impact |
|---|---|
| NIfTI viewer not included | NIfTI artifacts are metadata-only; use external viewer |
| No complete QC dashboard | Current UI shows summary, QC highlights, errors, not full analytical workspace |
| No report editor | Report artifacts are discoverable/previewable, not editable in-app |
| MATLAB/SPM/DPABI/GPU not executed | Contract-only backends; real execution requires `approved=true` and env opt-in |
| Electron app unsigned | Windows SmartScreen shows warning on first run |
| No macOS/Linux packaging | Windows-only for this release |
| `mock_store.py` is historical name | Implementation is `SQLiteDesktopStore`; rename pending |
| launcher build depends on conda mamba env OpenSSL DLLs | `pyinstaller_backend.spec` auto-detects conda prefix |
| No auto-update | Manual download for each release |

# MedImage Agent Developer Guide

本指南说明当前仓库的扩展入口。完整的安全、科学真实性、兼容性和验证规则以
[`AGENTS.md`](../../AGENTS.md) 为准，当前版本与能力边界以
[`PROJECT_STATE.md`](../../PROJECT_STATE.md) 为准。

## 1. 选择任务模式

修改前先按 `AGENTS.md` 选择最窄且能完整交付的模式：Focused Fix、Feature Bundle、
Architecture / Refactor、Scientific Validation、Release / Packaging 或 Documentation。
随后检查 `git status --short`，阅读目标文件、直接调用方、schema、存储和相关测试；
不得覆盖工作树中无关的用户改动。

## 2. 后端扩展路径

后端保持以下调用链：

```text
Route -> Request/Response Schema -> Service
      -> Runtime / Runner or Scientific Kernel
      -> State and Artifact Storage
```

新增领域接口时：

1. 在 `src/backend/app/schemas/` 定义结构化请求与响应。
2. 在 `src/backend/app/services/` 实现业务逻辑，并通过 `ProjectStore` Protocol 注入存储。
3. 在 `src/backend/app/api/` 创建或扩展对应领域 router；route 只负责 HTTP、依赖注入和
   结构化错误映射。
4. 在 `src/backend/app/main.py:create_app()` 注册新 router。
5. 对持久化 JSON 使用 `atomic_write_json()` 和 `_schema_version`；需要 SQLite 字段时同时
   提供兼容读取或迁移测试。
6. 补充 service、API contract、失败路径和重启恢复测试。

`src/backend/app/api/routes.py` 是遗留聚合入口，不是新增无关领域端点的默认位置。
公共 schema 也不应放回单体 `models.py`。

## 3. Pipeline Node 与科学计算

新增可执行 node 前先搜索是否已有 canonical kernel。实现时：

1. 将数值实现放在现有 scientific kernel/tool 层，runner 只调用共享实现。
2. 在 `src/backend/app/runtime/node_registry_plugins/` 的相应插件中注册稳定 `node_id`
   并导出 `REGISTRY`。
3. 同步 Node Contract、Tool Catalog、Approval Gate、Execution Ticket、唯一 Execution
   Gateway、审计、路径 allowlist 和能力展示。
4. 输出只能写入项目批准的 `work`、`logs`、`reports`、`derivatives` 或 `exports`；
   `rawdata/` 和登记源数据始终只读。
5. 验证数值产物存在且可重载，检查 shape、dtype、checksum、输入/参数绑定、backend、
   provenance 和部分失败行为。

计划、shape、路径或占位元数据不能标记为 `computed` 或 `validated`。MATLAB、SPM、
DPABI、GPU 和 DICOM 外部执行默认关闭；开启新路径属于受保护变更，必须有独立批准、
环境门控、审计、安全路径、失败处理和测试。

## 4. 前端扩展路径

前端通过共享 HTTP client 和批准的 Electron bridge 与后端通信，不直接访问文件系统或
执行外部程序。

1. 领域 API wrapper 放在 `src/frontend/src/lib/api/`。
2. 共享 TypeScript contract 放在 `src/frontend/src/lib/types/` 或相应领域 type 模块。
3. 业务界面和 controller/hook 放在 `src/frontend/src/features/`。
4. 可复用视觉组件放在 `src/frontend/src/components/`。
5. `App.tsx` 和 app shell 只保留应用壳与导航编排。
6. 用户可见文案同步 `src/frontend/src/i18n/messages/en.ts` 与 `zh-CN.ts`。

后端状态、Approval Summary、ticket、artifact 和 capability 始终权威。界面必须按适用
场景呈现 loading、empty、disabled、success、partial 和 failure，不能通过名称猜测或
本地乐观状态推断执行成功。

当前默认项目入口是 Agent Workspace；Runs 保存完整审计和技术证据，Settings 管理高级
显示与环境信息。兼容工作区可以保留深链接，但不应重新扩张为第二套流程。

## 5. Desktop 与打包

Electron 主进程和 preload 位于 `desktop/electron/`，Windows 构建脚本位于
`desktop/packaging/`。前端源码不在 `src/frontend/electron/`。

构建成功、sidecar health、packaged launch、renderer smoke、人工 GUI workflow 和真实
科学执行是不同证据层级，必须分别报告。日常验证只覆盖 canonical
`desktop/electron/dist/win-unpacked/`；installer、portable、签名和版本化产物只在显式
Release / Packaging 任务中生成。

## 6. 最小验证

后端 focused 变更先运行相关测试，共享基础设施变化再扩大到完整 suite：

```powershell
python -m pytest --collect-only -q --basetemp=.pytest_tmp
python -m pytest <focused-test-paths> --tb=short --basetemp=.pytest_tmp
python -m pytest --tb=short --basetemp=.pytest_tmp
```

每次 pytest 后按 `AGENTS.md` 仅清理仓库根目录直接子项 `.pytest_cache/` 和
`.pytest_tmp*`，并复查进程、残留和 `git status --short`。

前端源码或配置变更至少运行：

```powershell
npm --prefix src/frontend run format:check
npm --prefix src/frontend run typecheck
npm --prefix src/frontend run test
npm --prefix src/frontend run build
```

Electron 主进程、preload 或 packaging contract 变更至少运行：

```powershell
npm --prefix desktop/electron run check
```

## 7. 文档同步

接口、状态、配置、目录、能力、科学算法、安全边界、依赖或验证方式发生变化时，同一任务
必须同步对应 README、专项文档、能力矩阵、架构、安全或打包文档。历史发布记录只描述
对应版本，不按当前行为改写；完成的实施方案不继续留作当前待办。

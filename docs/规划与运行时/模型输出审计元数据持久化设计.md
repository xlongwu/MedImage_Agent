# Model-Output Audit Metadata Persistence Design

> M11-GUI-MODEL-T005 | Audit persistence for model-level events and decisions  
> Status: DESIGN | Date: 2026-07-11  
> Depends on: M11-GUI-MODEL-T001 through T004  
> Feeds into: M11-GUI-MODEL-T006 (mock-real boundary tests)

---

## 1. Executive Summary

This document defines how model-level audit metadata must be persisted when real fine-tuned GUI Agent inference is eventually introduced. Currently, audit is response-only (in-memory `GuiAuditRecord`). Persistent audit metadata enables traceability, debugging, and compliance — but it also creates a privacy risk surface. **This design mandates that audit persist only metadata, never raw content.**

## 3. Scope and Non-Goals

### Scope
- Define a unified audit metadata schema across all model pipeline stages.
- Define what may and may not be persisted.
- Define scoped audit file paths, naming, retention, and cleanup.
- Define audit failure behavior.

### Non-Goals
- Implementing audit persistence code — no file writes, no inference, no model loading.
- Enabling PyWinAuto, screenshots, clipboard, or new GUI actions.

---

## 4. Audit Persistence Threat Model

| Threat | Risk |
|------|:---:|
| Audit logs leak PHI | HIGH |
| Audit logs leak credentials/tokens | CRITICAL |
| Audit logs leak raw model prompts/outputs | HIGH |
| Audit logs leak chain-of-thought | MEDIUM |
| Audit path traversal to rawdata/derivatives | HIGH |
| Audit retention keeps sensitive data too long | MEDIUM |
| Audit failure silently removes accountability | MEDIUM |

**Principle:** Persist metadata only — IDs, statuses, decisions, reasons, hashes. Never persist raw screenshots, clipboard, credentials, tokens, PHI, or chain-of-thought.

| Event | When |
|------|------|

| `MODEL_INFERENCE_COMPLETED` | When inference finishes (future) |
| `MODEL_OUTPUT_RECEIVED` | When raw model output is received |
| `MODEL_OUTPUT_REJECTED` | When adapter rejects model output |
| `MODEL_OUTPUT_NORMALIZED` | When adapter maps to record_observation |

| `MOCK_PROVIDER_CALLED` | When MockGuiProvider.perform_step() returns |

Current implementation records events 8-15. Future real model integration adds events 1-7.

## 7. Forbidden Persisted Fields (19)

| Category | Fields |
|------|------|
| Screenshots | `screenshot_bytes`, `raw_screenshot`, `image_data`, `png`, `base64` |
| Clipboard | `clipboard_contents`, `raw_clipboard`, `clipboard_text` |
| Credentials | `api_key`, `token`, `password`, `secret`, `credential` |
| PHI | `subject_id` (unredacted), `patient_name`, `phi_raw` |
| Paths | `rawdata_path`, `derivatives_path`, `absolute_user_path` |
| Content | `raw_text`, `raw_json` (from model output, unless sanitized) |
| Reasoning | `chain_of_thought`, `reasoning`, `hidden_context` |
| Environment | `env_var`, `shell_history` |

**Rule:** Never persist raw model output or prompt. Store IDs, statuses, reasons, summaries only.

## 9. Audit File Path and Scope Policy

### Recommended Path
```
reports/gui/model_audit/<run_id>/model_audit_<timestamp>_<audit_id>.json
```

Alternative:
```
outputs/work/gui_agent/model_audit/<run_id>/model_audit_<timestamp>_<audit_id>.json
```

### Blocked Paths
- `rawdata/`, `data/`, `derivatives/` — permanent
- Absolute arbitrary paths
- Path traversal (`..`)
- Symlink escape
- Project root writes
- User-provided audit filename

### Naming Rules
- Audit writer generates filename from `run_id`, `timestamp`, `audit_id`.
- User cannot specify audit path.
- `run_id` and `audit_id` must be sanitized (alphanumeric + `_` + `-` only).

## 10. Retention and Cleanup Policy

| Policy | Detail |
|------|------|
| Default retention | Development: short (7 days); configurable |
| Configurable | `MEDIMAGE_MODEL_AUDIT_RETENTION_DAYS` env var |
| Cleanup | Manual command or scheduled cleanup script |
| Sensitivity | All persisted data is metadata-only — low privacy risk |
| Forbidden | Never store raw screenshots/clipboard/credentials (no retention needed) |

Since audit records contain only metadata (no raw content), retention risk is inherently low. Shorter retention is still preferred.

---

## 11. Audit Failure Policy

| Scenario | Behavior |
|------|------|
| Audit required, write fails | Block guard submission or inference |
| Audit fails after adapter rejection | Return rejection with `audit_failed` flag |
| Audit fails before provider call | Do not call provider |
| Audit directory creation fails | Block with `MODEL_AUDIT_PATH_BLOCKED` |
| Audit schema validation fails | Block with `MODEL_AUDIT_SCHEMA_INVALID` |

**Default: fail closed.** If audit is required and cannot be written, the operation is blocked.

---

## 12. Error Codes

| Code | Condition |
|------|------|
| `MODEL_AUDIT_SCHEMA_INVALID` | Audit record fails schema validation |
| `MODEL_AUDIT_PATH_BLOCKED` | Audit path is in forbidden directory |
| `MODEL_AUDIT_WRITE_FAILED` | Disk write failure |
| `MODEL_AUDIT_REQUIRED` | Audit is required but not configured |
| `MODEL_AUDIT_REDACTION_REQUIRED` | Redaction must be applied before persistence |
| `MODEL_AUDIT_FORBIDDEN_FIELD` | Audit record contains forbidden field |
| `MODEL_AUDIT_RETENTION_INVALID` | Retention config invalid |
| `MODEL_AUDIT_RUN_ID_INVALID` | `run_id` fails sanitization |
| `MODEL_AUDIT_OUTPUT_ID_INVALID` | `model_output_id` fails sanitization |

All failures: `provider_call_allowed=false`, safety flags all `false`.

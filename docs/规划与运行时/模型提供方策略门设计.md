# Model Provider Policy Gate Design

> M11-GUI-MODEL-T003 | Provider-level gate for real model access control  
> Status: DESIGN | Date: 2026-07-11  
> Depends on: M11-GUI-MODEL-T001, M11-GUI-MODEL-T002  
> Feeds into: M11-GUI-MODEL-T004 (input design)

---

## 1. Executive Summary

This document defines the **Model Provider Policy Gate** — the access-control layer that must gate every model inference request before any model runtime is invoked. Currently the system uses only static mock fixtures (`fixture_only`). Any future real model — local or remote — must pass this gate, and the gate must remain closed until a dedicated implementation phase with tests opens it.

**Current state:** Only `fixture_only` is allowed. All real providers are blocked. No weights are loaded. No inference is called.

## 3. Scope and Non-Goals

### Scope

- Define a taxonomy of model provider types.
- Define which providers are allowed, blocked, or design-only.
- Define the provider declaration schema for future real model access.
- Define the provider policy gate pipeline and error codes.
- Clarify the relationship between provider gate, runtime isolation, adapter, and GUI guard.

### Non-Goals

- Implementing the gate — no inference, no weights, no model loading.
- Enabling PyWinAuto or any real GUI provider.
- Opening new action types beyond `record_observation`.
- Changing the existing mock-fixture behavior.

## 4. Provider Taxonomy

| Provider Type | Description | Current Status |
|------|------|:---:|
| `fixture_only` | Static mock fixtures, no inference | ✅ Allowed |
| `local_allowlisted` | Local model, reviewed source, safetensors | ⏳ Design-only, blocked |
| `local_untrusted` | Local model, unverified source | ❌ Blocked |
| `remote_disabled` | Remote provider, explicitly disabled | ❌ Blocked |
| `remote_allowlisted_future` | Remote provider, future phase only | ❌ Blocked |
| `remote_untrusted` | Unknown remote endpoint | ❌ Blocked |
| `external_tool_provider` | Tool-calling agent, browser, shell | ❌ Blocked |
| `unknown_provider` | Unrecognized provider type | ❌ Blocked |

### Blocked Provider Names (Permanent or Until Dedicated Phase)

```
openai, local_llm, local_vlm, huggingface, ollama, vllm, transformers,
custom_http, pywinauto, desktop, browser, manual, unknown
```

**Key invariant:** `provider_type` name alone is never authorization. No environment variable, feature flag, or `approved=true` boolean can override the gate.

## 5. Current Allowed Provider Mode

**Only: `fixture_only`**

```
provider_type = "fixture_only"
provider_name = "mock_fixture_provider"
model_source = "fixture_catalog"
inference_enabled = false
network_access = "disabled"
```

Characteristics:
- Uses static mock fixtures from `gui_agent_mock_model_fixtures.py`
- No model weights loaded
- No inference called
- No network access
- No provider access
- Produces only Raw Model Output Envelope for adapter validation
- Only `record_observation` can result from adapter mapping

## 11. Provider Policy Gate Pipeline

```
1.  Validate provider declaration schema (all required fields present)
2.  Normalize provider_type (lowercase, strip)
3.  Reject missing provider_type          → MODEL_PROVIDER_MISSING
4.  Reject unknown provider_type          → MODEL_PROVIDER_UNKNOWN
5.  Allow fixture_only                    → MODEL_PROVIDER_ALLOWED
6.  Block local_allowlisted (phase gate)  → MODEL_PROVIDER_REAL_DISABLED
7.  Block local_untrusted                 → MODEL_PROVIDER_BLOCKED
8.  Block all remote types                → MODEL_PROVIDER_REMOTE_DISABLED
9.  Block external_tool_provider          → MODEL_PROVIDER_BLOCKED
10. Validate model_source (must match provider_type)
11. Validate weights_format (safetensors for real providers)
12. Validate checksum_required (true for real providers)
13. Validate trust_remote_code (must be false)
14. Validate weights_only (must be true)
15. Validate network_access (must be disabled)
16. Validate runtime_sandbox_required (true for real providers)
17. Validate inference_enabled (must be false in current phase)
18. Validate allowed_output_mode (must be raw_model_output_envelope)
19. Validate allowed_action_policy (must be record_observation_only)
20. Return structured result
```

**Current behavior:** Steps 1-5 execute; step 5 is the only path to `ok=true`. Steps 6-20 are defense-in-depth for future phases.

## 12. Relationship to Runtime Isolation

```
Provider Policy Gate        Runtime Isolation
─────────────────────       ───────────────────
Decides WHO is allowed      Decides HOW they run
Provider type, source       Weights loading, sandboxing
Network, checksum policy    Process isolation, resource budgets
Output mode, action policy  Prompt input, output envelope
```

Both are required. Passing the provider gate does not permit inference. Passing runtime isolation does not permit un-gated provider use. They are sequential gates in the model request pipeline.

---

## 13. Relationship to Adapter / Guard

```
┌──────────────────┐
│ Provider Gate    │  ← Controls model provider access
├──────────────────┤
│ Runtime Sandbox  │  ← Controls inference execution
├──────────────────┤
│ Adapter          │  ← Controls output normalization
├──────────────────┤
│ GUI Guard        │  ← Controls action execution
├──────────────────┤
│ MockGuiProvider  │  ← Only reachable provider
└──────────────────┘
```

**Authority boundaries:**
- Provider gate cannot grant GUI action permission.
- Adapter cannot grant provider permission.
- Model cannot grant either.
- Only the existing GUI guard can allow `MockGuiProvider` call.
- `provider_call_allowed` at each layer is independent: provider gate's `provider_call_allowed` refers to model provider access, NOT GUI provider access.

## 14. Error Codes and Response Schema

### Error Codes (15)

| Code | Condition |
|------|------|
| `MODEL_PROVIDER_POLICY_DISABLED` | Feature flag not enabled |
| `MODEL_PROVIDER_MISSING` | `provider_type` not specified |
| `MODEL_PROVIDER_UNKNOWN` | Provider not in taxonomy |
| `MODEL_PROVIDER_BLOCKED` | Generic block (untrusted, external tool) |
| `MODEL_PROVIDER_REAL_DISABLED` | Real provider not yet implemented |
| `MODEL_PROVIDER_REMOTE_DISABLED` | Remote provider blocked |
| `MODEL_PROVIDER_LOCAL_DISABLED` | Local real provider blocked in current phase |
| `MODEL_PROVIDER_SOURCE_NOT_ALLOWED` | `model_source` not allowed for this provider type |
| `MODEL_PROVIDER_CHECKSUM_REQUIRED` | Checksum required but not provided |
| `MODEL_PROVIDER_CHECKSUM_MISMATCH` | Checksum verification failed |
| `MODEL_PROVIDER_TRUST_REMOTE_CODE_BLOCKED` | `trust_remote_code=true` rejected |
| `MODEL_PROVIDER_NETWORK_BLOCKED` | Network must be disabled |
| `MODEL_PROVIDER_RUNTIME_SANDBOX_REQUIRED` | Sandbox required but not declared |
| `MODEL_PROVIDER_OUTPUT_MODE_BLOCKED` | Wrong output mode |
| `MODEL_PROVIDER_ACTION_POLICY_BLOCKED` | Action policy not `record_observation_only` |

### Response Schema — Blocked

```json
{
  "ok": false,
  "status": "MODEL_PROVIDER_BLOCKED",
  "error_code": "MODEL_PROVIDER_REAL_DISABLED",
  "provider_type": "local_allowlisted",
  "provider_name": "future_local_gui_model",
  "inference_allowed": false,
  "model_loaded": false,
  "network_accessed": false,
  "provider_call_allowed": false,
  "message": "Real model providers are disabled. Only fixture_only is allowed in the current phase."
}
```

### Response Schema — Allowed (fixture_only)

```json
{
  "ok": true,
  "status": "MODEL_PROVIDER_ALLOWED",
  "provider_type": "fixture_only",
  "provider_name": "mock_fixture_provider",
  "inference_allowed": false,
  "model_loaded": false,
  "network_accessed": false,
  "provider_call_allowed": false
}
```

**Note:** `provider_call_allowed=false` in both responses — this field refers to model provider access, not GUI provider access. It is always `false` at the model provider gate level because the gate does not grant GUI execution permission.

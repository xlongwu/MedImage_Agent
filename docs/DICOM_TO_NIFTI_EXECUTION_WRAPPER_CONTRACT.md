## 1. Purpose and Scope

This document defines the **Phase 4B DICOM-to-NIfTI conversion execution safety
wrapper** for MedImage Agent.  It specifies the command-template contract,
preflight checks, approval/audit requirements, output policies, and test
strategy required to safely convert FunRaw/T1Raw DICOM rawdata to BIDS-compatible
NIfTI outputs using `dcm2niix`.

**Explicit constraints — binding for the current phase:**

- **Real dcm2niix execution is DISABLED by default.**
- **No NIfTI files are written by the conversion service in this phase.**
- **No subprocess is spawned in this phase.**
- **This task does NOT enable SPM/DPABI/MATLAB/FSL/AFNI execution.**
- **This task does NOT enable full DPARSFA preprocessing.**
- **Rawdata remains read-only.**
- **All outputs must go under the project output directory.**
- **Research-use only, not clinical diagnosis.**

This contract is a **pre-implementation design document** that establishes
the safety wrapper, command-template schemas, preflight logic, and gating
conditions *before* any real `dcm2niix` call is made.

## 4. Input Layout Contract

### 4.1 FunRaw/T1Raw DICOM

```text
<rawdata_dir>/
├── FunRaw/
│   ├── Sub_001/*.dcm
│   ├── Sub_002/*.dcm
│   └── Sub_00N/*.dcm
└── T1Raw/
    ├── Sub_001/*.dcm
    ├── Sub_002/*.dcm
    └── Sub_00N/*.dcm
```

Detection: `funraw_t1raw_detector.py` — path-based, no pydicom required.

### 4.2 Mapping reuse

The 6 mapping previews generated by `conversion_planner.py` dry-run are reused
as the conversion execution plan.  Each mapping contains:

- `source_path` — absolute path to the DICOM subject directory
- `subject_id` — normalised BIDS subject ID (`sub-001`)
- `suggested_relative_path` — target BIDS output path
- `modality` — `func` or `anat`
- `suffix` — `bold` or `T1w`
- `confidence` — `high` for FunRaw/T1Raw layout

## 5. dcm2niix Command-Template Policy

### 5.1 Command template structure

Every dcm2niix invocation must be built from a `Dcm2niixCommandTemplate`,
never from a raw shell string.

```json
{
  "tool": "dcm2niix",
  "executable": "dcm2niix",
  "input_dir": "D:/DemoData/FunRaw/Sub_001",
  "output_dir": "C:/project/converted_bids/sub-001/func",
  "filename_pattern": "sub-001_task-rest_bold",
  "compress": "y",
  "bids_sidecar": true,
  "create_bids": true,
  "additional_flags": [],
  "command_preview": "dcm2niix -z y -f sub-001_task-rest_bold -o \"C:/project/.../func\" \"D:/DemoData/FunRaw/Sub_001\""
}
```

### 5.2 Invariants

| Rule | Enforcement |
|---|---|
| No `shell=True` | Command template stores argv list internally; `command_preview` is display-only |
| `input_dir` must be inside `rawdata_dir` | Validated at preflight |
| `output_dir` must be inside `project_dir` | Validated at preflight |
| `output_dir` must NOT be inside `rawdata_dir` | Validated at preflight |
| `executable` must match `dcm2niix` | Validated at preflight |
| `compress` must be `y` (gzip `.nii.gz`) | Default, can be overridden |
| `bids_sidecar` must be `true` | BIDS JSON sidecar is required |

### 5.3 Template generation

```python
def build_dcm2niix_command_template(
    mapping: DicomConversionMapping,
    output_root: str,
    executable: str = "dcm2niix",
) -> Dcm2niixCommandTemplate:
```

This pure function constructs the template from a dry-run mapping.  It does
NOT check whether `dcm2niix` exists on the system PATH — that is the job of
the preflight service.

## 6. Environment Flag Policy

Real `dcm2niix` execution requires ALL of the following environment flags
to be set to `"1"`:

| Flag | Purpose |
|---|---|
| `MEDIMAGE_ENABLE_DICOM_CONVERSION` | Gates DICOM conversion execution |
| `MEDIMAGE_MATLAB_ENABLED` | Not required for dcm2niix, but must be present for consistency |
| `MEDIMAGE_SPM_SMOKE_ENABLED` | Not required for dcm2niix, but must be present for consistency |
| `MEDIMAGE_ENABLE_REVIEWED_EXECUTION` | Gates reviewed-plan execution |
| `MEDIMAGE_ENABLE_REAL_PREPROCESSING` | Gates real preprocessing execution |

If ANY flag is missing or not `"1"`, the preflight returns
`status=disabled` and `conversion_disabled_by_default=true`.

- command templates (all 6 mappings)
- output root path
- approval context snapshot
- environment fingerprint

## 8. Output Directory Policy

```
<project_dir>/
└── converted_bids/                  ← dcm2niix outputs, NEVER rawdata_dir
    ├── sub-001/
    │   ├── anat/
    │   │   └── sub-001_T1w.nii.gz   (+ .json sidecar)
    │   └── func/
    │       └── sub-001_task-rest_bold.nii.gz  (+ .json sidecar)
    ├── sub-002/...
    └── sub-003/...
```

Invariants:
- `output_root` must be under `<project_dir>/converted_bids/`.
- `output_root` must NOT be inside `rawdata_dir`.
- No path traversal (`..`) in output paths.
- Overwrite policy: `fail_if_exists` by default.

## 9. Rawdata Read-Only Invariant

- No file in `rawdata_dir` may be opened for writing, appending, deletion,
  or renaming.
- Pre-execution and post-execution file count and checksum verification
  must confirm rawdata is unchanged.
- The `rawdata_read_only` safety flag is set on every response.

## 11. Manifest and Provenance Requirements

### 11.1 Output manifest

After (future) real execution, an `OutputManifest` must record:

- Every produced NIfTI file (6: 3 BOLD + 3 T1w)
- Every produced JSON sidecar (6)
- Manifest and provenance artifacts themselves
- `exists`, `size_bytes`, `sha256` verified for each item
- `missing_required_count` must be 0 for success

### 11.2 Provenance

An `ExecutionProvenance` record must capture:

- `dcm2niix` version (from `dcm2niix --version`)
- Input DICOM directory listing checksum
- Command templates used
- Environment fingerprint
- stdout and stderr log paths
- No shell command field (per `ExecutionProvenance` schema `extra='forbid'`)

---

## 12. stdout / stderr Log Requirements

- stdout and stderr must be captured to:
  `<output_root>/logs/dicom_to_nifti_stdout.log`
  `<output_root>/logs/dicom_to_nifti_stderr.log`
- Logs must be included in the output manifest as `stdout_log` and `stderr_log` artifacts.
- Logs must be previewable via the artifact discovery API.

## 13. Failure Handling

| Scenario | Status | Action |
|---|---|---|
| `dcm2niix` not on PATH | `disabled` | Preflight blocked; suggest install |
| Env flag missing | `disabled` | Return disabled response |
| Output root unsafe | `blocked` | Preflight blocked |
| `dcm2niix` returns non-zero | `failed` | Capture stderr, rollback partial outputs |
| Timeout | `timeout` | Kill process, rollback |
| Missing outputs | `failed` | Record in output manifest as missing |
| Rawdata changed | `blocked` (safety violation) | Block all downstream nodes |

---

## 14. Rollback / Cleanup Policy

If conversion fails mid-execution:
- All output files written by the conversion node must be removed
  (best-effort rollback).
- Partial NIfTI files, sidecars, and logs must not persist.
- A `DicomConversionFailureRecord` must be written recording the failure.

---

## 15. Retry / Resume Policy

Aligned with `docs/RUN_RETRY_RESUME_CONTRACT.md`:

- **Retry**: re-execute the conversion node.  Previous partial outputs are
  removed before retry.
- **Resume**: not applicable for conversion (it's the first stage).
- **Rerun**: fresh conversion from DICOM source.

Retry/resume is NOT implemented in the current phase.
